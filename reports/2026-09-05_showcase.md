# What the assistant does, from the record

**Date:** 2026-09-05
**Source:** the deployed database and telemetry, rendered by
`tools/showcase.py` into `reports/showcase/`. Nothing here is a screenshot
of a chat window: every page is the stored conversation itself — the
request, each tool call with its arguments, what the tool returned, the
picture the model looked at, the file it sent, the answer — and the run's
numbers from telemetry. The runs are the live scenario suite
(`scripts/loop_live.py`) executed inside the deployed worker on 2026-09-05
(`deployed-cf8c3774-*`, `deployed-99f16efe-*`), with the same image,
secrets, Volume and command runner a person's Telegram turn uses.

Regenerate at any time, read-only:

```powershell
.venv\Scripts\python.exe tools\showcase.py chat-r chat-s chat-p chat-f chat-i --user loop-live-check --out reports\showcase
```

## 1. A CSV turned into a chart, looked at, sent — [chat-r](showcase/chat-r.md)

*"In my workspace there is sales.csv … compute the total amount per
region, save a bar chart as chart.png, look at the chart to check it, send
it to me, and tell me which region has the largest total."*

`list_files` → `run_command` (pandas and matplotlib in one `python3 -c`) →
`read_file chart.png` (the PNG shown to the model as a picture) →
`send_file` → the answer names south, 45. Five model calls, 17.5 s.

![the chart the model made and looked at](showcase/chat-r-chart-ad6d85dc.png)

## 2. A failing script repaired from its traceback — [chat-s](showcase/chat-s.md)

*"check_calc.py fails when run with python. Run it, fix the bug in
calc.py so that it prints 'calc ok', run it again to prove it, and tell me
what was wrong."*

`run_command` (exit 1, `AssertionError: add(2, 3) gave -1`, and under it
the harness's own line: read the output, the traceback names the file and
the line) → `read_file calc.py` → `edit_file` (`a - b` → `a + b`) →
`run_command` again, exit 0, `calc ok`. Six model calls, 14.7 s.

## 3. A PDF made, checked, handed over — [chat-p](showcase/chat-p.md)

*"Make me a one-page PDF called apples.pdf about three kinds of apples,
check that the PDF really contains that text, and send it to me."*

The model writes the goal first — three lines, the last "Send the PDF to
the user" — then `pip install fpdf2` (already in the image), a script,
`python3 make_pdf.py`, `pdftotext apples.pdf -` to check, `send_file`.
Seven model calls, 28 s. The file it sent:
[apples.pdf](showcase/chat-p-apples-56a08e7d.pdf).

## 4. A page made and looked at — [chat-f](showcase/chat-f.md)

*"Write a small self-contained page counter.html with a heading, a button
labelled Count and a script that increments a number … Then open it with
inspect_page and tell me what the page contains."*

`write_file` → `inspect_page`, which opens the file offline in a real
browser and returns the structure, the visible text, console errors and a
screenshot. Three model calls, 15 s.

![the screenshot the model looked at](showcase/chat-f-image-caa9b5aa.png)

## 5. The way back to a result no longer on disk — [chat-i](showcase/chat-i.md)

The conversation had read `config.ini` two turns earlier; the file is
gone; the earlier result is a stub on the surface of the context. *"What
was the retry_timeout in the config we read earlier? Quote the line."*

`read_file` (not found) → `list_files` → `search_history` → `read_history`
by the position the stub names → `retry_timeout = 4711` quoted. Five model
calls, 6 s. This is the deployed run after ISS-0045, when a name with a
dot in it became findable in the Postgres store.

## What the record also shows

The same suite has the failures. G — a four-file Task Board with a
screenshot and the files sent to the chat — passes whole about one run in
three; the other runs hand the files over as paths (ISS-0003), and once
the model drew a white PNG with PIL and called it the screenshot
(ISS-0046). P's own check is stricter than the model: it counts a look
only as `view_pages`, and the model checks with `pdftotext`. All of this
is in `ISSUES.md` and in
`reports/2026-09-04_v2_isolated_execution_review.md` §12–§16, with the
run ids.

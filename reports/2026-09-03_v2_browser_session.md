## What was built

**`BrowserSession`** in `app/tools/chromium.py`, one page in a private browser
with the whole operation set the contract named:

```text
open(document | url)   snapshot(max_chars, query?)   screenshot(full_page?)
navigate(url)          evaluate(expression)          console()
click(ref)  type(ref, text)  press(key)  select(ref, value)
```

plus `visible_text`, `title`, `location`, `viewport` and `refused`. `close` is
the context manager `open_browser(...)`, which starts the process, applies the
boundary and always ends it.

**The snapshot** is an indented outline of the page, one line per element
that means something to a person: a role from the tag, input type or explicit
`role`, a name from `aria-label`/`alt`/`title`/label/placeholder or the
element's own text, and state (`value`, `checked`, `disabled`, `expanded`,
heading level, a select's options, a link's `href`). Hidden elements are
skipped. Every actionable element — link, button, textbox, checkbox, radio,
combobox, slider, spinbutton, tab, menuitem, switch, anything with `onclick`,
`contenteditable` or a tabindex — gets `[ref=eN]`, and the map from ref to
element is kept on the window, regenerated by each snapshot. A container is
named only by its author, never by its text, so nothing is said twice.
`query` keeps the lines that mention it; `max_chars` bounds the rest and a cut
says how many lines are missing. Formatting is Python, so it is tested without
a browser.

**Actions take refs, never selectors.** A ref not from the last snapshot, or
whose element has since left the page, is `browser.stale_ref` before anything
is sent to the browser. `click` is a real mouse press at the element's centre
after scrolling it into view; `type` focuses, selects what was there and
inserts text through the input path, so handlers fire; `press` sends a key by
its virtual code (`Enter`, `Tab`, arrows, or one character); `select` sets the
option by value or visible text and dispatches `input` and `change`.

**The boundary is a property of the session.** `open_browser(offline=True)`
blocks every network scheme before anything is opened and refuses `navigate`
to any address (`browser.refused`); `open_browser(allow=policy)` is the public
page, with the policy asked about every request. A session must have exactly
one of the two.

**`inspect_page`** is re-implemented on the session and returns a text report
in sections — title, browser, network rule, screenshot path, console errors,
the structure with refs, the visible text — plus the PNG. It exposes no
action, on purpose. **`render_locally`** in `app/web.py`, which the deployed
renderer function calls, drives the same session with the public policy; the
`Rendered` it returns is unchanged.

The codes are `browser.unavailable`, `browser.load_failed`, `browser.stale_ref`
and `browser.refused`, defined where they arise and re-exported by the tool
module.

## What was not built, deliberately

No `click`, `type`, `navigate` or `evaluate` tool for the model: the roadmap
says observation only in this version, and the product question those answer
(ISS-0008, judging a generated page by using it) waits for the scenario suite
to accept a change in what the model does. No session that outlives a call: a
tool opens, looks and closes, as before. No `hover`, `drag`, `fill`, dialogs or
tabs: none of the references' longer lists was needed to make the first click
possible, and adding one later changes nothing about `snapshot`.

Whether the exposed surface will be one tool with an `action` argument or
several tools is still the open question the references report left; nothing
here decides it, since nothing here exposes an action.

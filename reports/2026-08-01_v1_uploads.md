# Version 1 upload admission

**Date:** 2026-08-01

## Result

Uploads now have one authoritative, UI-independent admission boundary. Chainlit
applies the same policy early in its file picker, while `app/attachments.py`
checks the complete batch again before an agent turn starts. One rejected file
refuses the whole message, so the model cannot answer as though it saw a file
that was silently dropped.

The Version 1 allowlist is `image/jpeg`, `image/png`, `image/webp`, `audio/wav`,
`audio/x-wav`, `audio/mpeg`, `audio/flac`, and `audio/ogg`. Limits are five files,
20 MiB per file, and 50 MiB for the complete message. Empty and unavailable
files are also refused. Document handlers remain deferred; adding them does not
require a Chainlit-specific agent path.

- Browser DOM inspection of the real upload inputs showed the exact eight MIME
  types above and multiple-file selection. The model endpoint was not running
  or called.

The in-app browser could not automate the operating-system file chooser, so the
visible refusal message was not exercised through that picker. The same path is
covered offline: unsupported, empty, oversized, over-count and over-total
batches raise `AttachmentError`; `on_message` catches it, sends `Upload refused`
and returns before calling `agent.steps`.

## External actions and cost

Chainlit was restarted locally. No network provider, model request, GPU work,
download, database migration or destructive action occurred. External cost and
VRAM use were zero.

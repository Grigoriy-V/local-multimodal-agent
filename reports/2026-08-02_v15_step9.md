# Version 1.5 step 9 — working Chainlit task experience

**Date:** 2026-08-02

## Outcome

The bounded Snake graph is now a user-facing Chainlit capability rather than a
separate acceptance harness. The native composer exposes `task` and `preview`
commands. Both were exercised end to end in the running application.

`/task` now performs this product flow:

1. Gemma creates a structured plan.
2. Chainlit shows the exact task subdirectory, acceptance criteria and the
   `write_file`, `edit_file`, `browser_verify` permissions.
3. The user approves or declines the checkpointed task grant.
4. The bounded graph implements, verifies and naturally repairs while budget
   remains.
5. Chainlit shows status, elapsed time, iterations, tool calls, an inline PNG
   and a downloadable HTML artifact.

`/preview` accepts an absolute or relative HTML path only when it resolves
inside `workspace/`. After explicit confirmation it launches the isolated
browser probe, writes a uniquely named PNG beside the HTML and returns the PNG
inline plus the HTML file. Normal messages still use the conversational graph.

## Runtime boundary

`TaskRuntime` owns graph compilation, the separate task checkpoint SQLite,
canonical per-chat task identity, artifact resolution and preview path
validation. Chainlit remains a thin adapter for native commands, buttons,
steps, messages and elements. It shares the conversational agent's
`ModelBackend`, so provider access still stays behind one interface.

The websocket session ID was incorrectly used as a conversation ID before this
step. The adapter now uses Chainlit's canonical `session.thread_id`. A live
reload showed that later command exchanges appended to one existing canonical
thread instead of creating another sidebar artifact.

## Live product evidence

### Preview command

Input:

`D:\ML\local-multimodal-agent\workspace\v15-live-snake-20260802-02\snake.html`

Observed in Chainlit:

- the safe relative path appeared in the confirmation;
- `Open and capture` was required before writing;
- Edge `151.0.4129.59` loaded the document with no console errors;
- `snake-preview-dcea4fe3.png` appeared inline;
- `snake.html` appeared as a downloadable file.

The first live render exposed a missing MIME value that crashed the Chainlit
frontend. Every returned file/image now carries an explicit MIME type, and the
same scenario then passed.

### Task command

The first UI task exposed a path contract ambiguity: Gemma repeated the grant
prefix in `tasks/<id>/snake.html`, producing a nested duplicate and a three-
iteration stopped outcome. The implementer prompt now says to use exactly
`snake.html`, and the worker refuses a repeated grant prefix with a precise
tool error before it can create a nested path.

The repeated honest UI task then produced:

- canonical chat: `e4ab3fb7-6e59-4506-8bba-fadb81d18fd0`
- sandbox: `workspace/tasks/f9f12174d87a272c`
- status: completed
- iterations: 1
- tool calls including initial listing: 2
- graph elapsed after grant: 29.938 seconds
- checks: 10/10 passed
- artifacts: `snake.html` (6,104 bytes), `snake-preview.png` (7,828 bytes)
- final grant: revoked with `task completed`

After a page reload, the user request, completed status and preview image were
restored from the canonical conversation SQLite in the same chat.

## External actions, cost and limitations

The Chainlit process on port 8100 was restarted to load each corrected build;
the final process remains running. The already running local vLLM endpoint and
installed Edge were used. No downloads, remote publication or non-local
network access occurred.

The stopped and successful UI task runs consumed about 126.7 seconds of graph
inference time combined. Exact task token usage and VRAM were not sampled by
the UI runtime. The preview command used about two seconds of local browser
work and no model request.

Two test-created sidebar threads from before the canonical-ID fix remain in the
database because deleting user-visible history requires separate approval. A
resumed completed task restores its status text and PNG, but Chainlit's current
conversation schema does not persist an HTML file element; the downloadable
HTML link is present in the live result, while the saved history retains its
path and preview image.

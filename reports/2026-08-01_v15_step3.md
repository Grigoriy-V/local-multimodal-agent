# Version 1.5 step 3 — checkpointed task grant

**Date:** 2026-08-01

## Result

The task graph now requests one explicit grant after planning and before the
first implementation attempt. The approval payload shows:

- the normalized sandbox subdirectory;
- the only permitted destructive tools: `write_file` and `edit_file`;
- the plan summary and acceptance criteria.

An approved grant becomes active only for that task run. It resolves its root
inside the configured workspace again when used, cannot target the workspace
root or escape it, and is always changed to `revoked` when the task completes or
stops. A refusal revokes it without calling implementation or test handlers. If
there is no checkpointer, the safe outcome is refusal rather than an unasked
write permission.

The task deadline begins again after the user answers, so human review time
does not consume the execution budget. Planning itself remains bounded before
the approval request.

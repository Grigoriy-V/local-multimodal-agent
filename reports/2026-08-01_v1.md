**Date:** 2026-08-01
**Model:** `gemma-4-12b-it` (w4a16 QAT) on vLLM 0.26, `http://127.0.0.1:8000/v1`,
`max_model_len` 16384
**Code:** `app/models/`, `app/context/`, `app/agent/`, `app/memory/store.py`, `ui/`

## What was decided while building it

**The token count comes from the model, not from a tokenizer.** The contract
keeps tokenizers inside `app/models/`, and the rule survives inspection: a
tokenizer is part of a model, and a local text tokenizer cannot count what an
image costs. `usage.prompt_tokens` on the answer is the exact size of the
request that was just made — free, correct about images, and produced by the
model that will be charged for it.

**The ceiling comes from the server too.** `GET /v1/models` reports
`max_model_len`; `ModelBackend.context_limit()` exposes it and is asked once per
agent. Nothing in this repository configures the limit, so raising vLLM's
`--max-model-len` is the only change needed to give the agent more room.

**The fold is reactive and one turn late.** The trigger is the measured size of
the request already sent, so the turn that overshoots still fits and the fold
happens before the next one. The project configures a *fraction*
(`AGENT_CONTEXT_FRACTION`, default 0.6), and that fraction is exactly the
headroom that makes being late safe.

**`stream` is not retried, deliberately.** Half an answer has already reached the
user; retrying would repeat it. The docstring says so, so that it reads as a
decision and not as an omission.

**The default workspace is a sandbox.** `AGENT_WORKSPACE` now defaults to
`workspace/`, not `.`, and is created on first use. The safe answer is the
default one; asking the user which directory to grant belongs with the policy
work in version 2.

**A cut is clamped at the start of the conversation.** Found by the live run, not
by the tests — see below.

## Live evidence

`.venv\Scripts\python.exe -m scripts.v1_live`, one run, a temporary directory,
the real graph and the real model.

| Section | Result |
|---|---|
| The server states its limit | `context_limit: 16384`, budget `9830` at fraction 0.6 |
| One real turn is measured | `470 / 9830 tokens (5%)`, whole turn **0.5 s** |
| A short conversation over budget folds | budget 327 tokens; used 468, 483, 513; summarized through 0 → 2 → 4 |
| The fold summarizes rather than drops | `'The user asked the assistant to name one color… "Blue." … "Red."'`, message count still ahead of the summary's reach |
| The conversation list | `short 6 messages 'Name one colour.'`, `chat 2 messages 'Say hello in five words.'` |
| A dead endpoint | three attempts, **6.3 s**, `the endpoint http://127.0.0.1:9/v1 could not be reached (ConnectTimeout)`; `context_limit` returns `None` rather than raising |

The folding section deliberately runs at fraction 0.02 with
`summarize_after=1000`: every request overshoots and none is long, so a fold
there can only have been triggered by tokens.

### What the live run caught that the tests did not

`fold_older_messages` computed its cut as `len(pending) - keep_recent` and passed
it to `first_user_turn`. Before the token trigger existed, the message-count
guard made a short `pending` impossible. The token trigger removed that
protection: a conversation that is *short but over budget* reached the call with
a negative start, which Python reads as an index from the end — `IndexError` on
a nearly empty list, inside the graph, on a live turn.

The fix is in `first_user_turn`, which now clamps a negative start to the
beginning, so no caller can mean "from the end" by accident. Three offline tests
now cover it: a negative start on a short list and on an empty one, a thread
shorter than `keep_recent` that went over budget (nothing to fold, so nothing is
folded), and a thread already folded to nothing that must not fold again.

A second, smaller thing the run exposed: `httpx.ConnectTimeout` stringifies to
the empty string, so the error read `the endpoint could not be reached:` and
named neither the endpoint nor the failure. It now names both.

## Closing criteria

| Criterion | Evidence |
|---|---|
| The request is bounded by tokens, not by message count | live fold at fraction 0.02; `test_a_short_thread_that_filled_the_request_is_folded` |
| The bound is the model's own, not a copy | live `context_limit: 16384`; `test_the_limit_is_read_from_the_named_model` |
| A model that is silent about its limit is not guessed at | live dead endpoint returns `None`; `test_without_a_known_limit_only_the_message_count_folds` |
| Folding never loses a message | live message count ahead of the summary's reach; `test_nothing_is_lost_when_a_thread_is_folded` |
| A transient failure is retried, a permanent one is not | `test_a_busy_server_is_tried_again_and_the_answer_arrives`, `test_a_rejected_request_is_not_repeated` |
| The user can choose which conversation to open | live thread list; `test_a_thread_is_labelled_by_how_it_began` |
| An unreadable attachment is named, not dropped in silence | `test_an_ignored_attachment_is_named_so_it_can_be_reported` |
| The agent may only touch one directory | `AGENT_WORKSPACE` defaults to `workspace/`; the filesystem tools' existing root checks |

**188 offline tests pass**, up from 156 at the end of the previous step.

## Limitations

- **The Chainlit rendering itself is unverified by machine.** `media_parts`,
  `summarise`, `rejected` and `to_message` are tested; building a `cl.Image` and
  showing it needs a live Chainlit session, so that it looks right is only known
  by hand. The app was booted to confirm it imports and starts.
- **The fold is one turn late by design.** A single turn that jumps from well
  under the budget to over the model's whole limit — a large image pasted into a
  nearly full conversation — is not caught by the fraction. Nothing predicts a
  request's size before sending it.
- **The budget is asked once per agent.** Restarting vLLM with a different
  `--max-model-len` under a running UI leaves the agent on the old number.
- **The fraction is a blunt instrument.** 0.6 of 16384 is 9830 tokens; whether
  that is the right share is a judgement, not a measurement.
- **Retries are blind to which failures are worth waiting for.** The status list
  is fixed, and a connection error is always treated as transient.
- **The thread list shows the five newest.** Beyond that it would be a search
  problem, which version 1 is not.
- **The workspace is fixed at configuration time.** Choosing a directory in the
  UI, and asking the user before granting one, is version 2 policy work.

# Version 1.5 step 6 — repair loop and honest finalization

## Outcome

Closed the deterministic retry loop around the model worker and web verifier.
Every failed `TestReport` already produced graph feedback; this step proves that
the concrete model worker receives that exact feedback and can inspect and edit
the existing artifact on the next bounded attempt.

`ImplementationResult`, `TaskState` and `TaskOutcome` now retain normalized
relative paths for successful `write_file` and `edit_file` calls. Final outcomes
also retain the last report's unresolved failures. This keeps a stopped result
useful and prevents a generic model summary from hiding a failed verifier.

## Evidence

The integration test uses the real task graph, model worker, filesystem tools and
deterministic web verifier with a scripted model backend:

1. attempt 1 writes a structurally valid Snake draft without controls;
2. `game_controls` fails and its detailed failure reaches the next prompt;
3. attempt 2 calls `read_file`, then `edit_file` with an exact replacement;
4. the repeated verifier report passes and the graph completes.

Measured result: two implementation attempts, five total tool calls including
the automatic directory inspection on each attempt, one retained artifact
(`snake.html`) and zero final failures. A separate bounded test stops after two
failed attempts and retains both `draft.html` and `artifact: missing`.

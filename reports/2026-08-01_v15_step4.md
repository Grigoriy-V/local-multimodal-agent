# Version 1.5 step 4 — model task worker

**Date:** 2026-08-01

## Result

Added a model-agnostic task worker over `ModelBackend` and connected it to the
checkpointed task graph.

- Planning requests a strict structured object containing a concise summary,
  steps and acceptance criteria; invalid or incomplete JSON stops as a readable
  task-stage failure.
- Each implementation attempt resolves the active grant root, creates that
  subdirectory when necessary and takes an authoritative `list_files` snapshot.
- Gemma receives only filesystem tool schemas rooted at that task directory.
- `write_file` creates, while repairs can inspect with `read_file` and change one
  exact match with `edit_file`.
- Every requested tool call is counted, including the automatic initial
  inspection. Calls beyond the remaining allowance receive tool errors and do
  not execute.
- Exact tool successes and failures are appended to the next model request.
  For example, an ambiguous edit returns its real `found 2 matches` result.
- Expected backend, planning and implementation failures become honest stopped
  task outcomes instead of graph crashes.

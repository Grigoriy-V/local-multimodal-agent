# Version 1.5 step 3 — high-level agent mode

**Date:** 2026-08-02

## Result

Chainlit now exposes a native `Conversation` / `Agent` setting. In agent mode a
normal text request enters the application task runtime without a slash command
or per-tool button. The graph plans first, requests one explicit workspace
grant, implements through the shared capability registry, runs its currently
available checks, and reports artifacts and bounded-run statistics.

The configured workspace root can be granted explicitly. Relative paths resolve
from that root, and absolute paths remain accepted only when they resolve inside
it. The task grant uses the same `filesystem.read` and `filesystem.write`
capability names as the general registry.

## Evidence

- Offline regression: `294 passed in 7.08s`.
- Chainlit restarted on port 8100 and returned HTTP 200.
- Browser check confirmed the native settings panel contains both `Conversation`
  and `Agent`, and the selected mode can be confirmed without a tool command.
- The already-running local Gemma endpoint passed `scripts.doctor`.
- Outcome-only runtime task: create `.agent/smoke/agent-mode-step3.txt` containing
  exactly `AGENT-MODE-OK`.
- The model produced its own plan and criteria, requested the workspace grant,
  selected filesystem operations, created the artifact, and completed in one
  iteration. The file was independently read as exactly 13 characters.

## Deliberate limitation

Step 3 does not pretend that artifact existence proves task acceptance. Its
temporary task-agnostic check proves only that reported artifacts exist and are
non-empty, and the UI states this limitation. Task-derived validation modality,
real evidence evaluation, and autonomous repair belong to Version 1.5 step 4.
If a task produces no artifact, the graph stops honestly with validation
unavailable instead of wasting its retry budget or claiming success.

Agent mode accepts text tasks at this step. Multimodal task input, richer
progress/evidence display and cancellation remain later roadmap work.
